# Ovimuu

Telegram-бот + Telegram Mini App: напоминания о приёме лекарств/витаминов с ИИ-вводом (фото, голос, текст) и лёгкой геймификацией (маскот Ови, XP, уровни).

Сейчас это **прототип** для 1–5 пользователей (автор, жена, пара знакомых). Не усложнять архитектуру ради масштаба.

## Документы

- `docs/brief.md` — исходное продуктовое ТЗ (от заказчика, жены автора).
- `docs/decisions.md` — **принятые решения. Они важнее ТЗ**: где расходятся, прав `decisions.md`.
- Перед любой заметной задачей перечитай нужный раздел `decisions.md`. Если решение нужно поменять — предложи и спроси, не меняй молча.

## Стек

- TypeScript везде, Node.js 22 LTS, pnpm workspaces.
- `apps/bot` — бот + HTTP API для Mini App в **одном процессе**: grammY (+ `@grammyjs/conversations`, `@grammyjs/menu`), Hono для API.
- `apps/miniapp` — React + Vite + `@telegram-apps/sdk-react`.
- `packages/db` — PostgreSQL 16 + Drizzle ORM + drizzle-kit миграции.
- `packages/ai` — интеграции Yandex Cloud: SpeechKit (STT), Vision OCR, YandexGPT. Наружу только интерфейс (см. ниже).
- Очередь/планировщик: **pg-boss** поверх того же Postgres. Без Redis.
- Валидация: zod (env, ответы ИИ, тела запросов API).
- Деплой: Docker Compose (postgres, app, caddy) на VPS Timeweb Cloud. Caddy отдаёт статику Mini App и проксирует `/api`, HTTPS автоматически.

## Ключевые правила продукта (не нарушать)

1. **ИИ ничего не додумывает.** Нет данных — `null`, бот уточняет у пользователя. ИИ никогда не предлагает препараты, дозировки или изменения схемы.
2. **Ничего не активируется без подтверждения пользователя.** Распознанное расписание — черновик (`drafts`), пока пользователь не нажмёт «Всё верно». Изменения схемы — предпросмотр «было → станет» + подтверждение. Единственное исключение: «отметить приём» применяется сразу с кнопкой «Отменить».
3. **Отправленное напоминание ≠ принятый приём.** Без ответа статус `not_marked`, не `taken` и не `skipped`.
4. **XP начисляется ровно один раз за приём** — уникальный ключ в БД, а не проверка в коде.
5. **Никакого чувства вины.** Нет серий (streaks), нет штрафов, Ови не грустит/не болеет из-за пропусков. Тексты тёплые, короткие, без «Ты снова пропустила».
6. **Медицинские вопросы** («можно ли X с Y») — вежливый отказ и совет спросить врача/фармацевта.
7. **Фото и сырой OCR-текст не храним** после распознавания. В логах — без содержимого медицинских данных.
8. Время в БД — UTC (`timestamptz`). Часовой пояс пользователя — IANA-строка в настройках.

## Архитектурные правила кода

- Весь ИИ — за интерфейсом в `packages/ai`:
  - `transcribe(audio: Buffer, mime: string): Promise<string>`
  - `ocr(image: Buffer): Promise<string>`
  - `parseMedications(text: string, ctx: UserContext): Promise<ParseResult>`
  - `routeIntent(text: string, meds: ActiveMedSummary[]): Promise<IntentResult>`
  Ответы модели всегда валидируются zod-схемой. Невалидный ответ → одна повторная попытка → понятное сообщение пользователю.
- Логика доменная (расписание, генерация приёмов, XP) — чистые функции без зависимостей от grammY/Hono, покрыты тестами (vitest). Особенно: генерация приёмов на день, часовые пояса, якоря, повторы.
- Кнопки и callback'и обрабатываются кодом, без вызова ИИ.
- Mini App авторизуется через `initData`: проверка HMAC на бэкенде на каждый запрос, `user_id` берётся только из проверенных данных.
- Пользовательские тексты бота — на русском, вынесены в один модуль `texts.ts` (не размазывать по хендлерам).
- Идентификаторы, комментарии в коде, коммиты — на английском.
