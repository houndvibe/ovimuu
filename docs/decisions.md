# Ovimuu — принятые решения

Документ фиксирует решения, принятые при обсуждении ТЗ (`docs/brief.md`). Где решения расходятся с ТЗ — действуют решения.

---

## 1. Цель и команда

- Прототип для 1–5 человек: основной тестировщик — жена автора, позже пара знакомых.
- Код целиком делает автор (frontend-разработчик, React/TS). Персонажа Ови рисует жена.
- Юридические требования к медданным (152-ФЗ, согласия, уведомления) — **перед бетой**, не сейчас. Но архитектура не должна этому мешать: хостинг и ИИ в РФ, минимизация хранимых данных.

## 2. Стек и инфраструктура

См. `CLAUDE.md`. Кратко: TS-монорепо, grammY + Hono в одном процессе, React + Vite Mini App, Postgres + Drizzle, pg-boss, Docker Compose + Caddy на **Timeweb Cloud**.

Перед арендой сервера проверить стабильную доступность `api.telegram.org` с него. Бот в проде — на webhook (через Caddy), в разработке — long polling.

## 3. ИИ — Yandex Cloud

- Голос → **SpeechKit** (распознавание). Голосовые Telegram приходят в OGG/Opus — SpeechKit принимает этот формат напрямую. Синхронное распознавание ограничено по длительности/размеру аудио — проверить актуальные лимиты в документации; для длинных голосовых либо асинхронный API, либо просить говорить короче.
- Фото → **Vision OCR** (с поддержкой рукописного текста) → текст.
- Текст → **YandexGPT**:
  - разбор назначений (`parseMedications`) — более сильная модель;
  - маршрутизатор намерений (`routeIntent`) — лёгкая модель (Lite).
  - Ответ строго JSON: использовать структурированный вывод по JSON-схеме, если доступен, иначе JSON-режим + валидация zod.
- ИИ вызывается **только** на свободный текст, голос и фото. Кнопки — без ИИ.
- Весь ИИ спрятан за интерфейсом в `packages/ai`, чтобы провайдера можно было заменить одним модулем.

## 4. Модель данных

### Сущности (набросок, уточнить при реализации)

- **users** — `id`, `telegram_id` (unique), `first_name`, `created_at`, `consent_at`, `onboarding_step`.
- **user_settings** — `user_id`, `timezone` (IANA), якоря распорядка: `wake`, `breakfast`, `lunch`, `dinner`, `sleep` (time), `repeat_count` (0–2, по умолчанию 1), `repeat_delay_min` (30).
- **medications** — `id`, `user_id`, `name`, `dose_amount` (numeric, nullable), `dose_unit` (мг, МЕ, мл… nullable), `units_per_intake` (numeric), `unit_form` (таблетка, капсула, капли…), `notes`, `created_at`.
- **schedules** — `id`, `medication_id`, `frequency_type` (`daily` | `every_n_days` | `weekdays` | `once`), `every_n_days`, `weekdays` (int[]), `start_date`, `end_date` (nullable = бессрочно), `status` (`active` | `paused` | `completed`), `paused_until` (date, nullable).
- **schedule_slots** — `id`, `schedule_id`, либо `time` (точное), либо `anchor` (`wake` | `breakfast` | `lunch` | `dinner` | `sleep`) + `anchor_offset_min` (например, +30 = «через полчаса после завтрака»; по умолчанию 0).
- **intakes** — конкретный приём: `id`, `user_id`, `medication_id`, `schedule_id`, `slot_id`, `scheduled_at` (timestamptz), `status` (`pending` | `taken` | `snoozed` | `skipped` | `not_marked`), `confirmed_at`, `reminder_message_id`, `reminder_group_id`.
- **drafts** — черновики распознавания и предпросмотры изменений: `id`, `user_id`, `kind` (`add` | `change`), `payload` (jsonb), `status` (`open` | `confirmed` | `cancelled` | `expired`), `expires_at` (+24 ч).
- **xp_events** — `id`, `user_id`, `kind` (`intake` | `day_complete`), `intake_id` / `date`, `amount`. **Уникальные индексы**: `(intake_id)` для `intake`, `(user_id, date)` для `day_complete`.
- **user_progress** — `user_id`, `xp_total`, `level`, `days_with_ovi`.
- **unlocks** — `user_id`, `item_key`, `unlocked_at`, `equipped` (bool).
- **ai_feedback** — кнопка «ИИ ошибся»: `id`, `user_id`, `kind`, `input_text`, `model_output` (jsonb), `created_at`. Исключение из правила «не хранить сырой текст» — сохраняется только по явному нажатию пользователя.

### Поддерживаемые схемы

- Несколько приёмов в день; слот = точное время или якорь.
- Каждый день / каждые N дней / по дням недели / разовый приём.
- Курс с датой окончания или бессрочно. Пауза до даты. Завершённые курсы.

### Не поддерживаем в прототипе

Ступенчатые дозы («3 дня по 2, потом по 1»), приём «по необходимости», циклы («21 день пьём, 7 перерыв»). ИИ помечает такое полем `unsupported_reason`, бот честно объясняет и предлагает разбить вручную на несколько записей.

### Генерация приёмов

- `intakes` **не создаются на месяцы вперёд.** Ежедневная задача (pg-boss cron) создаёт приёмы на следующие сутки для каждого пользователя с учётом его часового пояса; при создании/изменении схемы — сразу пересоздаются будущие `pending`-приёмы на сегодня и завтра.
- Изменения схемы касаются только будущего. `taken`/`skipped`/`not_marked` не трогаются никогда.
- История хранится, пока пользователь сам не удалит данные.

## 5. Поток «фото / голос / текст → расписание»

1. Голос → `transcribe`, фото → `ocr`, текст как есть. Дальше единый путь.
2. `parseMedications(text)` → JSON по схеме п. 4, любое поле может быть `null`, плюс `unsupported_reason`. Промпт: игнорировать шапку клиники, ФИО, диагнозы — извлекать только назначения; **никогда не угадывать** дозу/время/частоту.
3. **Код** проходит по черновику и находит недостающие обязательные поля (название, количество за приём, время/якорь, периодичность). Уточняет **по одному**, кнопками где возможно: «Магний: как часто? [Каждый день] [Через день] [Другое]».
4. Черновик сохраняется в `drafts` (живёт 24 ч), можно вернуться позже.
5. Подтверждение в чате одним сообщением со всеми карточками: [Всё верно] [Исправить] [Отмена].
   - Этап 1: «Исправить» = «напиши, что поменять» → текст снова через ИИ с текущим черновиком в контексте.
   - Этап 2: «Исправить» открывает экран подтверждения в Mini App.
6. Только после «Всё верно» создаются `medications`/`schedules`/`schedule_slots` и генерируются приёмы.
7. Фото и сырой OCR-текст удаляются сразу после разбора.

## 6. Изменение расписания фразой

- Любое свободное сообщение (не в процессе уточнения) → `routeIntent(text, activeMeds)`.
- В модель передаётся список активных препаратов пользователя: `id`, название, краткая схема.
- Ответ: `intent` ∈ `add` | `change_time` | `change_amount` | `pause` | `complete` | `delete` | `mark_taken` | `other`; `targets` (id из переданного списка); `params`.
- `add` → поток п. 5.
- Сопоставление с препаратами проверяет **код**: несколько кандидатов или ни одного → уточнение кнопками.
- `change_*`, `pause`, `complete`, `delete` → сообщение «было → станет» + [Подтвердить] [Отмена].
- `mark_taken` → применяется сразу, сообщение с кнопкой [Отменить] (действует несколько минут).
- `other`: болтовня → короткий дружелюбный ответ; медицинский вопрос → «Советов по лечению я не даю — лучше спроси врача или фармацевта».

## 7. Напоминания

- Приёмы с одним `scheduled_at` → **одно сообщение**: «☀️ Утренний квест: витамин D — 1 капсула, омега-3 — 1 капсула». Кнопки: [Приняла всё] [Позже] [Пропустить], при >1 препарате ещё [Отметить по отдельности].
- **Позже** → [15 мин] [30 мин] [1 час] → новая задача pg-boss. Схема не меняется, статус `snoozed`.
- **Нет ответа** → повторов `repeat_count` (по умолчанию 1) через `repeat_delay_min` (30). Повтор — короткое «Ови напоминает 🌿» **ответом (reply) на исходное сообщение**; кнопки остаются в исходном. Повтор не отправляется позже якоря «сон».
- В конце дня (по TZ пользователя) неотвеченные `pending`/`snoozed` → `not_marked`. Это отдельный статус от `skipped`.
- После нажатия исходное сообщение **редактируется**: «✅ Принято в 9:12 · +10 XP» + [Отменить].
- Отметка задним числом (на вчерашнем сообщении) — засчитывается, `confirmed_at` = время нажатия. XP — только если прошло ≤ 24 ч от `scheduled_at`.
- Все задачи планировщика идемпотентны (повторная доставка задачи pg-boss не шлёт второе сообщение).
- Тихих часов в прототипе нет.

## 8. Ови — формат ассетов

Вариант прототипа: **статичные изображения + CSS-анимация**.

Требования к ассетам (для жены):

- PNG или WebP с прозрачным фоном, **единый холст** для всех файлов (например, 1024×1024), Ови в одной и той же позиции.
- Состояния: `idle` (ожидание), `happy` (задание выполнено), `rest` (нет задач), `greet` (новый день / приветствие), `levelup`.
- Для моргания — пары кадров с открытыми/закрытыми глазами (минимум для `idle`).
- **Аксессуары — отдельными слоями** на том же холсте, накладываются поверх любого состояния.

Код: компонент `<Ovi state="happy" accessories={[...]} />`. Анимации на CSS: дыхание (scale), моргание (смена кадра), подпрыгивание на `happy`, появление на `greet`. Поддержать `prefers-reduced-motion`. Внутренности компонента можно позже заменить на видео-клипы или Rive без изменения остального кода.

В боте Ови присутствует картинкой в онбординге и (опционально) в поздравлении с уровнем.

## 9. Игровая система

- **+10 XP** за подтверждённый запланированный приём (≤ 24 ч от `scheduled_at`).
- **+20 XP** бонус за день, если подтверждены все запланированные на этот день приёмы (и их было ≥ 1).
- Разовые приёмы, добавленные «на сейчас», XP **не дают**.
- Уровень: чтобы перейти с уровня N на N+1, нужно **100 × N XP**.
- Награды: уровень 2 — аксессуар №1, уровень 3 — аксессуар №2. Дальше пока только поздравление.
- **Никаких серий.** Накопительный счётчик «дней с Ови» (никогда не уменьшается).
- Пропуски, `not_marked`, завершение курса — без штрафов и без потери прогресса.
- Отмена отметки «Приняла» отменяет и XP этого приёма (удаление `xp_events`, пересчёт прогресса).

### Навигация Mini App

Три вкладки снизу:

- **Сегодня** (по умолчанию): Ови (небольшой), уровень и XP, прогресс дня, список приёмов с кнопками, ссылка «Мои препараты», кнопка «+», шестерёнка настроек.
- **Ови**: персонаж крупно, уровень, аксессуары (надеть/снять), что откроется дальше.
- **История**: календарь с цветными статусами, детали дня по тапу, список завершённых курсов.

«+» → [Фото] [Голос] (закрывают Mini App, бот присылает подсказку в чат) / [Текст] [Вручную] (остаются в Mini App).

Использовать тему Telegram (цвета из `themeParams`) как основу, поверх — палитра из ТЗ (тёплый белый, молочный, бежевый, приглушённый зелёный/оливковый). Haptic feedback на «Приняла».

## 11. Онбординг (в чате)

1. Приветствие от Ови: картинка `greet` + 1–2 фразы.
2. Согласие: «Чтобы распознавать фото и голосовые, я отправляю их в Yandex Cloud. Фото не сохраняю — только итоговое расписание. Удалить всё можно в любой момент: /delete» → [Понятно]. Сохранить `consent_at`.
3. Часовой пояс: кнопки с вероятными вариантами + [Другой] (ввод города/смещения).
4. Якоря: «Обычно я считаю так: подъём 8:00, завтрак 9:00, обед 13:00, ужин 19:00, сон 23:00» → [Подходит] [Настроить].
5. Сразу: «Расскажи, что ты принимаешь: голосом, фото или текстом» → поток п. 5.

Не спрашивать имя, не объяснять XP заранее, не предлагать Mini App до первого расписания.

## 12. Отладка и обратная связь

- Кнопка **[ИИ ошибся 🙈]** под каждым черновиком и предпросмотром изменения → запись в `ai_feedback`.
- `/stats` (только для `ADMIN_TELEGRAM_ID`): отправлено напоминаний, отвечено (и медианное время ответа), `not_marked`, среднее число правок черновиков, число записей `ai_feedback`.
- Логи структурированные (pino), без содержимого медицинских данных.

## 13. Порядок работ

**Этап 1 — бот (выкатить и отдать на тест как можно раньше)**

1. Монорепо, docker-compose (postgres), env через zod, базовый grammY-бот в polling.
2. Схема БД + миграции.
3. Онбординг.
4. `packages/ai`: transcribe / ocr / parseMedications / routeIntent + zod-схемы + тестовые фикстуры.
5. Поток добавления: черновик → уточнения → подтверждение → создание схемы.
6. Генерация приёмов (чистые функции + тесты на часовые пояса и якоря) + pg-boss.
7. Напоминания: группировка, Приняла / Позже / Пропустить, повторы, редактирование сообщения, `not_marked`.
8. XP и уровни (с уникальными ключами) + сообщения о наградах.
9. Изменение схемы фразой (маршрутизатор + предпросмотр + подтверждение).
10. `/delete`, `/stats`, кнопка «ИИ ошибся».
11. Деплой на Timeweb: Caddy, webhook, бэкапы Postgres (ежедневный `pg_dump`).

**Этап 2 — Mini App (параллельно с тестированием бота)**

1. Авторизация через `initData` (HMAC) + API на Hono.
2. Экран «Сегодня».
3. «Мои препараты» + ручная форма + редактирование.
4. Экран подтверждения черновика (интеграция с «Исправить» в боте).
5. «История».
6. Ови + аксессуары (когда будут ассеты; до этого — заглушка).
7. Настройки.

**Подключение знакомых** — после 7 дней использования ботом без сбоев напоминаний (не пришло / пришло не вовремя / пришло дважды).
